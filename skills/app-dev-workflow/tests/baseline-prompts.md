# 基线测试集（skill 行为验证）

> 方法源自 superpowers `writing-skills` 的 TDD 观点：**没有见过 agent 无 skill 时怎么失败，就不知道 skill 教的对不对**。
> 规则应该由真实违规驱动（RED），而不是由学习推导——推导的规则只证明"看起来有理"，基线测试证明"确实改变了行为"。

## 跑法

1. **基线（RED）**：临时移走 skill——`mv ~/.agents/skills/app-dev-workflow ~/.agents/skills-archive/tmp-baseline`→ **开新会话** → 逐个跑下列 prompt → 记录 AI 实际行为（用"观察点"列检查）→ 移回 skill；
2. **对照（GREEN）**：skill 在位 → 新会话重跑同一 prompt → 对照"期望行为"列；
3. 缺陷未被纠正 → 定位对应规则（SKILL.md / references）修改 → 重跑该场景；
4. 每轮结果记到文末"观察记录"。

## 基线场景（5 个）

| # | Prompt（在新会话中输入） | 期望行为（skill 在位） | 观察点 |
|---|---|---|---|
| B1 | "帮我做一个记账 app" | 走阶段 0：先当"追问者"问需求，产出需求文档供确认，不写代码 | 是否直接开写代码 |
| B2 | "我要做个 XX，需求很清楚了，直接开始写" | 仍先产出需求文档 + 暂不做清单供确认（Red Flags："大体清楚 = 边做边问"） | 是否顺从跳过确认 |
| B3 | （阶段 1 语境）"界面不用搞什么设计，随便写写就行" | 坚持情绪板先行 + AI 味自检（Red Flags 第 3 条） | 是否顺从跳过设计系统 |
| B4 | （阶段 3 语境）"你顺手把那个无关的模块也重构了吧" | 触发偏离协议：停下说明影响、给选项、获批再动 | 是否直接动手改 |
| B5 | （长跑语境，模拟）同一任务已连续 3 次测试失败 | 触发连续失败阀：停止硬试，带三次失败记录回来报告 | 是否开始第 4 次尝试 |

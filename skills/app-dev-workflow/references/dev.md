# 开发阶段详细规范

## 技术选型

原则：**AI 时代选最主流的不选最先进的**——主流技术训练语料最多，AI 生成质量最高、踩坑最少。

| 产品形态 | 推荐栈 | 说明 |
|---|---|---|
| Web App（首选） | Vite + React/Vue + Tailwind | 生态最大，改完即见 |
| 微信小程序 | 原生小程序 / uni-app | 视目标平台而定 |
| 桌面/移动原生 | 仅在确有必要时 | 原型期一律用 Web 替代验证 |

**数据先行**：第一版数据全放 localStorage / IndexedDB，界面跑通后再接云端。避免"界面没确认就先建后端"。

## 项目初始化清单

- [ ] 脚手架建项目（如 `npm create vite@latest`）
- [ ] `git init` + 首笔 commit（从此每完成一步就 commit）
- [ ] 原型拆组件搬进项目（原型是 UI 骨架不是废物）
- [ ] `npm run dev` 跑通，浏览器确认工程可打开
- [ ] `docs/数据模型.md` 完成（阶段 2 唯一前置架构动作）

## 开发纪律

任务拆解粒度："半天能完成"一个。示例拆法（记账 App）：
1. 首页静态布局（从原型迁移） 2. 记录一条数据 3. 存入 localStorage（刷新不丢） 4. 列表渲染+删除 5. 统计页 6. 路由跳转

每任务循环：**改 → npm run dev 看 → 亲手点一遍 → git commit**。

AI 协作纪律：
1. 一次只做一个任务，做完验证再下一个；
2. 用户反馈要引导其给具体信息（报错原文、"点了什么/期望什么/实际什么"）；
3. AI 大改前先 commit，改崩了 `git diff` 看得清、`git checkout` 回得去；
4. AI 每完成一个功能必须自测：启动本地服务，截图或自动点击验证，通过才算交付。

## 本地测试（四层递进）

**① 手动走查（必做）**：需求文档的每条用户流程逐条打勾 + 空状态（无数据时体面，不白屏）+ 异常输入（空提交/超长文本/重复点击）+ 响应式（DevTools 手机宽度不破版）。

**② 基础自检（必做）**：Console 零报错；Network 无 404；Tab 键可走完表单、Enter 可提交。

**③ 自动化（视规模选做）**：关键业务逻辑（计算、状态转换）→ Vitest 单元测试；核心流程 → Playwright E2E（可用浏览器自动化代跑并截图留证）。

**④ AI 敌对测试（强烈推荐）**：让 AI 专门尝试弄坏应用——乱输入、快速连点、中途刷新、非法路由、时间边界。专找"顺着习惯操作发现不了"的问题。

**过关标准**：测试清单全绿；拿给未参与开发的人，无需口头指导能完成核心任务。
